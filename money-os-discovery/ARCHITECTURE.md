# Discovery Engine Architecture

## Overview
This architecture ensures total separation of concerns between Money OS's transactional SaaS layer (Product Engine) and the organic growth layer (Discovery Engine).

## Core Principles
1. **Total Isolation**: No auth, no dynamic API calls to the core platform, no user state.
2. **Static First**: All content is pre-rendered via Static Site Generation (SSG) for maximum performance and near-zero runtime execution costs.
3. **Crawlability Optimized**: Native markdown/MDX compilation structured with explicit LLM and search engine schemas (JSON-LD).
4. **Vercel Edge Ready**: Hosted on a separate Vercel project to fully isolate bandwidth and caching behavior from the main product.

## Content Collections (Astro Content API)
- `docs/`: Versioned developer and user documentation.
- `blog/`: Time-stamped articles, heavily relying on MDX for rich embedding.
- `changelog/`: Release notes grouped by month/week.
- `comparisons/`: "Money OS vs [Competitor]" matrices.
- `use-cases/`: Niche-specific pages (e.g., "Money OS for Freelancers").

## Automation Readiness
- The repository structure supports CI/CD injection.
- The `src/content` folder acts as the target for the future **AI Content Pipeline**, where an automated publisher (e.g., GitHub Actions / n8n) can commit new `.mdx` files generated by the Content Engine.

## Why Astro over Next.js?
While Next.js excels at dynamic, authenticated state (which we use for the SaaS), Astro strips out all JavaScript by default (Zero JS architecture). This is critical for achieving perfect Lighthouse scores and zeroing out compute costs, allowing the site to scale to thousands of pages entirely on Vercel's Free tier constraints.
